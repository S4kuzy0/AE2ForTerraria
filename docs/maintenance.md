# 测试、部署与故障排查

维护基线：0.26.5；核对日期：2026-10-16（北京时间）。安装构建命令与变量定义统一见[仓库 README](../README.md#从源码构建)。开发机器专属位置只保留本地，不写入通用文档。

## 更新流程

1. 阅读[项目记忆](project-memory.md)、相关需求和设计，核对当前版本、实际启用列表与 Git 差异。
2. 建立实际可读取的恢复点，包含受影响的未提交文件、必要配置和已安装包；不能只因文件被 Git 跟踪就认定已有备份。
3. 完成已授权改动，并同步修订指南、需求、设计、验证记录和项目记忆中的相关事实。
4. 运行与风险相称的静态检查和回归。代码版本递增 `build.txt`，使用完整源码路径在 tModLoader 安装目录构建；构建直接安装到实际存档目录。
5. 核对编译输出、包大小与写入时间；必要时记录哈希。正在运行的客户端重启后才能加载新包。
6. 检查待上传内容，建立明确说明改动和验证范围的提交，推送私有仓库，核对远程提交与可见性。

纯文档变更进行内容、链接和上传检查，不递增模组版本或覆盖安装包。仅规划或预览的任务按指定范围处理。不要把生成包、测试结果或本地工作指令加入提交。

## 分层验证

| 验证层 | 适用检查 | 不能据此证明的内容 |
| --- | --- | --- |
| 编译 | 类型、API 与构建打包 | 物品守恒、界面交互或完整兼容性 |
| 静态资源/键 | 类名贴图与本地化引用 | 实际贴图加载、布局、动态键与第三方绘制 |
| 核心回归 | 账本、事务、配方、权限、协议与拓扑夹具 | 两台实际客户端持续游玩、所有第三方回调 |
| 实际客户端 UI | 原生绘制、布局、滚动、控件场景与恢复 | 全部人工输入法和真实鼠标操作 |
| 隔离世界玩家旅程 | 世界更新、绘制、保存重载与脚本驱动交互 | 未执行的正常角色选择路径、人工长期游玩 |
| 真实联机 | 两端实际存取、任务、权限、断线与重连 | 未注入的网络故障或所有恶意客户端场景 |

测试要使用实际存档目录和当前启用列表。服务端跳过纯客户端模组且不加载 UI/贴图，不能替代完整客户端验证。启动真实客户端前告知用户会打开游戏窗口。

### 静态检查

在仓库根目录，使用可用的 Python 3：

```powershell
python tools/check_assets.py
python tools/checkkeys.py
git diff --check
```

资源检查结果写入被忽略的 `validation/asset-check.json`。两项 Python 工具采用源码正则检查；贴图覆盖包括可识别的继承链，但显式 Texture override 和动态本地化键仍需要人工或客户端核验，不能宣称静态检查穷尽所有情况。

### 服务端加载与核心检查

先按仓库 README 设置 `$TmlInstall` 和 `$SaveDirectory`，确认实际启用列表。以下仅加载服务器，不打开玩家原始世界：

```powershell
Push-Location $TmlInstall
try {
    & (Join-Path $TmlInstall 'dotnet\dotnet.exe') (Join-Path $TmlInstall 'tModLoader.dll') -server -tmlsavedirectory $SaveDirectory -autoshutdown
} finally {
    Pop-Location
}
```

不要添加 `-nosteam`，否则创意工坊内容会被跳过。需执行显式核心夹具时，在启动该进程前设置 `AE2_RUN_REGRESSION=1`，完成后清除本次设置。测试会暂借全局状态，避免与正常游戏会话并行。

### 客户端核心、UI 与旅程

`AE2_RUN_REGRESSION=1` 启用客户端核心夹具，`AE2_UI_REGRESSION=1` 启用菜单 UI 验证。`tools/run_client_validation.ps1 -Run <新的运行标识> -Mode core` 可启动这组检查，但脚本目前使用本机固定路径，运行前必须核对；输出目录已有同名记录时换用新标识。

玩家旅程通过 `AE2_PLAYER_JOURNEY` 和该脚本的 `journey` 模式启用。它依赖本地专用测试世界，源码仓库不包含这些存档。新机器不能直接假定可运行；先建立独立测试世界与临时角色，验证范围后再启用。不要用玩家原始世界补上缺失夹具。

日志必须出现对应完成标记：`AE2 REGRESSION COMPLETE`、`AE2 UI REGRESSION COMPLETE`、`AE2 JOURNEY COMPLETE`；同时检查 `FAILED`、异常与夹具恢复记录。测试进程退出或模组菜单出现，都不等于测试通过。`validation/stage2/` 的独立 harness 是历史辅助输入，需检查当前 API、生成文件与 .NET 9 SDK，不替代本版真实 tML 检查。

本轮确认的根因与修复：

- 用户原日志记录 `UIElement.Update` 的集合修改异常，来源为缩放期间重排终端子控件。回调改为完整子树更新后处理；下拉菜单自我移除走同一安全时机。
- 真实拖动诊断确认手柄确实收到按下、松开，但靠边尺寸被错误限制。当前 tML 在 UI 上下文中已缩放 Main 屏幕尺寸，现统一使用 `PlayerInput.OriginalScreenSize / Main.UIScale`。菜单分辨率夹具也同步原生屏幕缓存并完整恢复。
- 窄窗口的旧装配室状态文字曾撑出边界。核对当前程序集后，确认 `UIText.Recalculate` 会通过 `InternalSetText` 重写最小宽度；现在在内部文字变更回调中约束，弱引用表避免重复注册。边界检查已通过。

版本采用统一默认尺寸和 `.compact1` 偏好键：首次忽略旧尺寸，旧记录保留供回滚，以后读取并保存新调整。实际查看小分辨率查询页、驱动器、合成详情、旧装配室以及世界中连续缩放后的访问终端截图。没有改变物品身份、账本保存、配方规则或通信协议。

本版未进行两台真实客户端持续游玩、全部人工输入法及复杂缩放组合、所有第三方条件回调的穷尽验证。旅程在真实客户端更新和绘制链中注入 PlayerInput，并使用原生槽位回调，不是操作系统鼠标宏。既有世界副本的原生右键检查来自 0.26.3，本轮未重做；当时用户已反馈原角色重进后恢复正常，原会话具体根因未确认。

第三方 `InfiniteAddPointSystem` 首次入图的 PreUpdate 异常仍单独记录，未擅自修改或禁用该模组。历史测试中 Fargo 新角色介绍卡片曾覆盖机器输入，只在隔离测试角色清理，不能把这一历史结论等同于所有交互故障的原因。

## 部署、分发与 Git 同步

构建成功后，产物直接写入实际存档目录的 `Mods/AE2ForTerraria.tmod`。服务器与客户端一起升级到相同版本。检查包时间和大小，防止把旧包或异常小包当成新包；不把具体字节大小永久写成固定合格阈值。

用户需要分享成品时，再把本次已验证包复制到本地 `dist/`，文件名带版本号并附 SHA256。源码推送不会自动发布创意工坊、GitHub Release 或安装到其他电脑，这些是独立操作。

上传前查看差异、按本次范围暂存，再执行 `python tools/check_git_upload.py`。检查器读取暂存区并拦截指令文件、个人配置、构建产物和常见密钥格式；它不是完整秘密识别器，仍需查看待提交文件。`tools/sync_git.ps1` 会按允许目录收集变更，若有与本次无关的用户改动，不直接调用它批量混入，应按文件暂存、检查、提交并普通推送。

GitHub CLI 凭据保存在系统凭据存储；本机辅助程序位于被忽略目录。新机器需自行安装 Git/GitHub CLI 并登录。使用无空提交的明确提交消息，推送前后核实仓库私有、远程分支包含本次提交。发生分歧时不强推覆盖；认证或网络失败保留本地提交并如实报告。

## 常见故障

| 表现 | 检查与处理 |
| --- | --- |
| 构建报告无法加载 ReLogic | 在 tModLoader 安装目录运行构建，检查项目导入位置与安装是否完整 |
| 包异常小、名字空白或版本异常 | 确认 `-build` 后接源码完整路径，重新构建并检查输出及时间；不要直接加载坏包 |
| 游戏仍显示旧版本 | 检查实际存档目录是否正确、包是否覆盖成功，重启客户端 |
| 服务端测试只剩少量本地模组 | 检查是否误加 `-nosteam` 或使用了错误存档目录 |
| MissingResourceException | 检查实际类名、继承、Texture override 与打包资源；静态通过后仍需真实客户端加载 |
| 界面文字是键名或乱码 | 核对 HJSON 键前缀、中英文键、动态键和字体；不要往游戏字体不支持的字符串中加入图标字符 |
| 终端没有库存或一直等待 | 确认访问/合成入口、设备连接、权限和读取代次；多人检查服务器回包及版本，不能直接修改显示缓存伪造成功 |
| 任务不执行 | 依次检查材料、工作站、环境、暂停、权限、空间、有限搜索与特殊回调提示；保留原料，不用作弊补产物掩盖问题 |
| 换盘被阻止 | 当前类别位或每身份数量超过替换后的容量；先转移或取出物品，不直接删除账本 |
| 箱子总线不工作 | 检查原版容器接触格、原点、模式、过滤、锁定与目标容量；第三方存储容器不支持 |
| 新角色首次入图报第三方异常 | 按堆栈区分来源，在隔离角色复现；记录启用列表，不擅自修改或禁用用户模组包 |
| 推送出现 EOF、连接重置 | 先核对远程是否已收到提交，再安全重试；本机历史曾以 Git HTTP/1.1 或 CLI 禁用 HTTP/2 成功重试，确切网络根因尚未确认 |
| Windows Git 的 schannel 握手失败 | 先保留提交；本机曾用 `git -c http.sslBackend=openssl -c http.version=HTTP/1.1` 单次推送并核对远程成功。保持证书校验，不把临时重试当作已确认网络根因 |
| 指令文件被检查器拒绝 | 保留本地文件，核对忽略规则并取消跟踪；不得强制加入或再次上传含指令文件的旧历史 |

部署方式、协议、脚本参数或故障处理改变时，更新本手册；新的验证结果按实际版本和日期记录，不覆盖历史事实。
