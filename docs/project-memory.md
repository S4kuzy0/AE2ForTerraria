# 项目记忆

最后核对：2026-10-16（北京时间）；源码基线：0.26.5。
本文件记录可共享的项目上下文和长期事实。机器绝对路径、个人配置、凭据与助手工作指令保留本地，不复制到这里。使用前结合源码、Git 状态和最新用户要求重新核对。

## 已确认目标与约束

- 以真实启用模组环境开发和验证，实际启用列表是依据；不能用曾经记录的模组数量替代检查。
- 存储总线只支持原版箱子系统，这是允许的设计，不列入第三方存储接入计划。
- 在已授权范围内默认直接实施 UI 与非 UI 更新；用户仅规划、仅预览或使用 `/plan` 时遵从当次范围。历史必须预览后安装的规则已于 2026-10-10 取消。
- 代码版本完成后递增版本、构建安装并验证；纯文档与版本管理配置变更不发布模组新版本。
- 文档随代码维护，记录关键知识即可，不为简单函数堆积说明。界面操作和报错反馈用清楚的中文。
- 使用现有私有仓库 [S4kuzy0/AE2ForTerraria](https://github.com/S4kuzy0/AE2ForTerraria)，助手完成更新后自动提交、推送并核验。
- 存档、个人配置、备份、产物、日志、提取的预览素材与助手指令文件不上传。指令文件只保留本地；此前误上传历史已按用户要求清理，不得重新引入旧历史。
- 自动上传是助手处理更新时的步骤，不是外部工具每次保存后的后台监控。

## 技术与决策

| 事实或决定 | 理由、依据与影响 |
| --- | --- |
| C# 12 / .NET 8 / tModLoader | 当前模组项目配置；.NET 9 仅用于部分历史独立 harness，不是游戏运行要求 |
| 继续使用 tML 生命周期和直接模块调用 | 既有架构记录选择可维护的边界，未引入容器、数据库或独立服务器；不要无依据扩大技术栈 |
| 物品账本存在设备实体，磁盘只供容量 | 换盘不迁移物品；必须检查剩余容量，不能把盘当成携带库存的物品 |
| 身份包含规范化自定义数据，保存采用 ItemIO | 避免词缀/自定义物品合并，避免仅按会变化的运行时编号存档；旧数字记录仍有兼容边界 |
| 合成先规划、再复核、事务整体提交 | 输出空间、权限或回调变化时不丢材料；超出规划预算保留有限搜索状态 |
| 新版合成终端内置队列和工作站 | 新网络无需 CPU/装配室；旧设备和旧保存结构保留兼容，不能强拆带物品设备 |
| 访问终端与合成终端分开 | 存取、远程绑定属于访问入口，配方/任务/工作站/补货属于合成入口 |
| 网络策略按持久成员关联 | 几何锚点变化或网络合并/拆分不能静默丢失授权和锁定 |
| 服务器执行真实业务，客户端发送意图 | 回包须完整验证、匹配事务及读取代次；显示缓存不承担权威扣账 |
| 存储总线不硬接第三方容器 | 没有通用接口，强依赖与脆弱反射不符合已确认范围 |
| 特殊合成回调安全拒绝自动执行 | 无法表达为存储事务的副作用不能通过忽略回调解决 |

## 已排查过的坑

| 问题 | 有效处理或当前边界 |
| --- | --- |
| 使用另一套存档或用 `-nosteam` 测加载 | 改用实际存档目录并保留 Steam 发现；服务端仍跳过纯客户端模组 |
| 仅传模组名构建或在错误目录运行 | `-build` 传源码完整路径，在安装目录执行，核对产物时间与大小 |
| 服务端通过但客户端缺贴图/UI 崩溃 | 补静态资源和实际客户端验证，分别报告证据 |
| 旧坐标数字类型导致角色加载异常 | `TagCompat` 读取原始数值并兼容转换；保留旧字段读取 |
| 配方数组重排后索引指向错误 | 最终索引在 `PostSetupRecipes` 重建，不能只信早期加载索引 |
| 只按物品编号存储、部分存入清空整格 | 使用完整身份和余量守恒；加载旧数据不按新容量截断 |
| 合成先扣料、再遇到输出/条件失败 | `StorageTransaction` 准备和复核后整体提交；0.26.1 支持空间不足时逐批尝试 |
| 多 CPU 被首队列阻塞、取消或撤权后继续旧任务 | 轮转候选，保存真实所属任务；执行前重新验证状态和权限 |
| 过期/重复/截断游标回包覆盖手持物品 | 0.26.1 增强事务号、去重、身份与完整解码检查 |
| 无权限玩家收到管理数据、截断快照局部替换 | 按接收者权限发送，完整校验后发布，撤权清陈旧状态 |
| 多格设备子格不能被远程绑定/箱子解析识别 | 使用规范类型与原点；不能仅按旧单格 TileType 判断 |
| 上传连接重置与 CLI EOF | 重试前核对远程提交；曾用 HTTP/1.1 或 CLI 禁用 HTTP/2 成功，尚未确认确切根因 |
| Windows Git 的 schannel TLS 握手失败 | 2026-10-15 使用单次命令 `git -c http.sslBackend=openssl -c http.version=HTTP/1.1` 推送并查询远程成功；未关闭证书校验、未更改全局 Git 配置；确切网络根因未确认 |

旧版交付记录提供问题背景，不自动证明当前版本或新环境的全部路径已通过。

## 当前状态与下一步

**已核对事实：**源码版本 0.26.5，协议版本 \(7\)。2026-10-16 读取实际启用列表为 \(39\) 个模组；早期列表不再作为当前依据。最终验证范围见[维护手册](maintenance.md#已知验证基线)。

**本轮完成：**修复右下角缩放期间重排父级正在枚举的子控件集合；下拉菜单关闭也延后到子树更新结束。窗口边界使用 `PlayerInput.OriginalScreenSize / Main.UIScale`，避免 UI 上下文重复缩放。所有 \(13\) 类窗口默认 \(475 \times 350\)，主标签 \(80 \times 22\)；`.compact1` 键首次忽略旧尺寸，保留旧偏好记录并继续保存新调整。窄分类栏采用原有分类和子分类选择，拉宽后展开；驱动器、管理页及旧装配室重排，旧装配室也改用原版背包。文字更新回调约束动态标签最小宽度，避免重算后文字撑出窗口。未修改账本、物品身份、配方条件、旧设备实体代码或协议。

**本轮检查：**最终同一安装包零错误、零警告；核心 \(616\)、UI \(504\) 项通过，保留 \(93\) 个渲染场景。完整世界旅程 \(88\) 项通过，包含实际按住手柄缩放、世界更新继续且数量不变、原版背包、存取、即时合成、重叠拦截、满盘加盘恢复和保存重载。资源 \(34\) 项、中英文 UI 键各 \(436\) 项无缺失。原有存档及备份 \(138\) 个文件摘要未变，布局和配置内容未变；Magic Storage 选项只有 gzip 时间戳变化。新增测试自动备份已逐成员核对与隔离测试相同。证据为本地 `validation/release-0.26.5.json`、`client-0.26.5-final.log` 和 `player-journey/v0265-journey-verified`。

**重要排错依据：**旧缩放测试只单独更新手柄，无法覆盖父级枚举异常；现改为完整状态更新。世界测试先确认按下、松开确实到达手柄，再定位重复 UIScale 换算造成的边界限制，不把未生效的拖动算作通过。菜单分辨率夹具必须同步并恢复 `PlayerInput` 原始屏幕缓存。`UIText.Recalculate` 会调用 `InternalSetText` 重写 MinWidth，单次清零不足；内部变更回调已验证有效，弱表防止重复注册。历史 0.26.3 的详情历史、容量预检及交互排查，以及 0.26.4 的即时合成与完成提示仍保留。

**未解决或未验证：**原会话“所有 ME 方块无法右键”未在既有世界副本复现；安装后用户使用原角色重进并明确反馈“好了”。原会话的具体根因未确认，测试中的一次类似现象来自 Fargo 新角色介绍卡片，不能直接等同。两台真实客户端持续联机、断线恢复、人工输入法/鼠标与复杂缩放矩阵、Recipe Browser 全功能逐项对照、第三方 `InfiniteAddPointSystem` 首次入图异常修复、机器路径参数化仍未完成。

**后续候选：**若再次出现交互失效，结合原生输入占用者追踪，不以容量已满为假设起点。真实联机与恢复验收、第三方首次入图异常、查询功能对照和人工输入检查仍可继续完善。路径参数化未经修改不得写成已完成。

## 2026-10-15 交互故障排查依据

- 最新用户要求：移除“合成列表”标题，将可合成筛选左对齐；修复详情返回/前进；存不下应提前说明且保留物品，满类别后仍能打开驱动器加盘。故障描述为单人、全部 ME 方块右键无反应，原生背包与挖其他方块正常。截图提示来自含工作站终端的拆除保护，不能据此认定磁盘溢出。
- 原有 `CanReplaceDisk` 已允许旧超额存储逐张增加容量，无需再改；类别满时既有身份仍可存入，旧超额存储仍可取出。原生开窗入口没有容量拒绝条件。
- 新增旅程检查必须使用原生 MouseRight 输入，不能只直接调用 `ModTile.RightClick`。首次失败已定位为新角色入图介绍卡片：原生 `Vanilla: Achievement Complete Popups` 层将 `mouseInterface` 设为真，挡住机器目标。只在独立测试角色中清理入图通知；未改第三方模组或用户设置。此结论只解释测试干扰，不证明用户原故障同因。
- 一次诊断 JSON 大小写同名字段导致测试异常，已更名；一次扩展满盘检查在改变分辨率后使用旧点击位置，已让注入点击逐帧跟随实际控件。两次失败不能用来证明正式业务缺陷。修正夹具后扩展完整旅程已通过。
- `run_client_validation.ps1` 增加 interactions 模式：只读复制显式指定的真实世界及附属保存到白名单测试目录，校验副本摘要，使用独立新角色逐格打开既有设备，完成后不保存副本。原文件不能成为激活路径或保存目标。副本检查已通过；用户随后确认原角色重进也恢复正常。普通客户端已移交用户，不再为文档收尾重启它。

## 如何接续与更新记录

开始工作时先读本文件和相关文档，确认 `build.txt`、源码接口、实际启用列表、工作树与远程状态。旧假设与现状冲突时，以最新明确要求和实际文件为准，并在这里记录变更背景。

重要决策、有效排错结果、阶段交付与遗留问题及时写入本文件；具体接口放设计文档，验收证据放维护记录，不重复粘贴聊天。记录必要日期、版本、证据名称和验证方法；不记录密钥、个人资料或整份配置。交接前更新状态，提交后以 Git 历史作为变更依据，不手写预测的提交编号。
