# 设计与数据说明

适用源码：0.27.10；核对日期：2026-10-19（北京时间）。源码根目录为 `AE2ForTerraria/`。本文件记录模块边界与关键数据流，不逐个解释简单函数。历史架构记录见 [ARCHITECTURE-0.22.md](ARCHITECTURE-0.22.md)。

## 技术与模块边界

项目使用 C# 12、.NET 8 和 tModLoader 的 `Mod`、`ModSystem`、`ModPlayer`、`ModTileEntity` 生命周期。它是游戏内模组，没有独立 Web 服务、数据库或常驻后台同步进程。

| 模块 | 职责 | 主要文件 |
| --- | --- | --- |
| 入口与配置 | 快捷键、消息分派、服务器配置 | `AE2ForTerraria.cs`、`MEConfig.cs` |
| 身份与存储 | 身份、数量、容量、稳定保存、事务提交 | `Core/ItemKey.cs`、`ItemPersistence.cs`、`StorageLedger.cs`、`StorageTransaction.cs` |
| 规划与执行 | 索引、路线、条件、回调边界和预算调度 | `Core/RecipeIndex.cs`、`CraftPlanning.cs`、`RecipeExecutionPolicy.cs`、`TerminalCraftingExecutor.cs` |
| 网络与业务 | 设备原点、连通、聚合、存取、策略和绑定 | `Systems/MachineTiles.cs`、`MENetwork.cs`、`NetworkInventory.cs`、`StorageOperations.cs`、`NetworkRegistry*.cs`、`MEPlayer.cs` |
| 数据与进度 | 掉落、商店、NPC、拼音和阶段推断 | `Systems/GameDataIndex.cs`、`NpcIndex.cs`、`PinyinIndex.cs`、`Acquisition/`、`Progression/` |
| 联机协议 | 解码、授权、确认、订阅和分片快照 | `Systems/MENet*.cs`、`InventoryTransactionInputSystem.cs` |
| 游戏内容 | 物品、设备实体、贴图、配方和成就 | `Content/Items/`、`Content/Tiles/`、`Content/Achievements/` |
| 界面 | 焦点、窗口、选择、反馈和业务入口 | `Systems/UISystem.cs`、`AEUiSession.cs`、终端读状态与策略状态、`UI/` |
| 验证 | 显式启用的核心、UI 和玩家旅程夹具 | `Systems/*Regression*.cs`、`RegressionChecks.cs`、筛选后的 `validation/stage2/` |

`Core` 仍依赖 Terraria 类型，不能直接作为不依赖游戏引擎的类库。界面调用共享业务或发送意图，协议校验后进入业务；账本不承担 UI、玩家拾取或网络授权。

## 关键接口

| 契约 | 约束 |
| --- | --- |
| `IMEStorage.Ledger` / `Allows(ItemKey)` | 驱动器和存储单元提供账本与分区接收规则 |
| `IPartitionedStorage` | 提供过滤列表、白名单标记和失效通知，避免 UI 各自修改缓存 |
| `StorageOperations.DepositInventory` / `Withdraw` | 单人与服务端共用，使用真实物品，不能把显示条目当权威库存 |
| `StorageOperations.PreviewDeposit` | 使用完整身份、分区和账本模拟插入，只读返回可接收量及拒绝原因；联网显示不替代权威操作 |
| `CraftPlanner.Plan` | 对只读库存规划；返回消耗、产出、中间余料、配方、缺料和有限搜索状态，不直接扣物品 |
| `StorageTransaction.TryApply` | 模拟并复核接收、容量和状态；成功整体提交，失败保留原数据 |
| `MENet.Handle` | 校验协议和消息方向，再分派服务端或客户端对应域 |
| `TerminalReadState` / `TerminalPolicyState` | 使用终端位置和会话代次限定快照归属，避免旧窗口数据污染新窗口 |

0.27.2 的终端模式继续区分旧访问入口与合成设备能力，存取能力对两类入口共用；合成设备目录按完整身份合并库存与已核验制作输出。0.27.3 只保留库存、可合成及两者并集三个范围，范围与排序复用 `UIChoiceMenu` 下拉；打开或收起菜单不重建列表，选择后才应用，当前项高亮。只读、未授权和过期网络快照仍由既有权限及事务检查拒绝，未新增协议或存档字段。0.27.4 改为普通左键通过 `StorageOperations.WithdrawToCursor` 取一叠至原版鼠标槽，悬停 R 进入 `UIBrowserDetails`；终端不绑定双击取出全部。R 使用当前鼠标命中项，文字输入、弹层及鼠标在窗口外时不触发；命中终端时阻止原版坐骑快捷键。联机增加光标取物意图，复用同一请求序号、原版槽位同步和权威完成回包；服务端复核终端类型、使用权限、物品锁及空光标，按完整身份扣账并记录审计。协议升级为 \(8\)，世界及角色保存格式不变；子页重排后保持右下角缩放手柄处于最前层；终端详情取消入场横移，避免首帧操作行超出宽度。工作站留在目录，详情页提供合成及取出操作。

0.27.3 将共享窗口、按钮、物品底色及配方详情改为泰拉瑞亚风格蓝色；下拉触发器保留独立绘制的箭头和文字空间。`LegacyContentVisibility` 隐藏旧访问终端的 AE 目录及制作配方，研究数量归零，类、方块、掉落和绑定代码保留。未增加依赖或修改网络包体。菜单回归使用 `WindowLayout.IsolatePersistence` 将真实关闭保存写入独立文件，预加载个人默认布局并恢复内存快照，不改变普通游戏的保存目标。

## 数据如何保存

| 数据 | 内存表示 | 保存方式 |
| --- | --- | --- |
| 物品身份 | `ItemKey`：运行时类型、词缀、预留变体和规范化 `ItemIO` 数据 | `ItemPersistence` 使用稳定物品内容保存；数量、收藏不参与身份 |
| 存储数量 | `Dictionary<ItemKey, long>`、版本和容量限制 | 驱动器/存储单元实体 `TagCompound`；加载采用恢复逻辑，不按新容量截断旧内容 |
| 磁盘与工作站 | 实际 `Item` 槽数组 | 设备实体保存；磁盘不携带账本，工作站保留完整物品数据 |
| 任务与补货 | 持久任务标识、目标、剩余量、请求人、暂停和库存目标 | CPU 与合成终端实体；终端继承队列宿主，额外保存工作站 |
| 网络策略 | 成员关联、名称、所有者、权限、锁定和有限审计 | `NetworkRegistry` 世界数据；几何锚点负责定位，持久成员关联保持策略归属 |
| 绑定与磁铁 | 按世界区分的访问终端绑定、玩家开关 | `MEPlayer` 角色数据，兼容旧坐标字段 |
| 布局与收藏 | 本机几何与稳定内容名称 | `Main.SavePath` 下的 `AE2ForTerraria-Layout.txt`、`AE2-BrowserFavorites.json` |
| 模组配置 | `MEConfig` 与过滤定义 | tModLoader 服务器侧配置；实际个人/服务器配置文件不提交源码仓库 |
| 索引与快照 | 配方、掉落、聚合视图、终端缓存 | 可重建数据；加载、卸载、换世界和相关版本变化时失效 |

新物品保存不依赖跨会话恒定的数字编号。缺失模组使用 tModLoader 占位物品，并保留缺失过滤引用。旧纯数字格式只能兼容校验，不能承诺恢复已经失去来源的任意历史编号。

## 主要操作流程

**存取：**界面产生槽位、身份与数量意图。单人进入共享业务；多人由服务器检查玩家与网络权限，再按服务端背包和账本执行。部分成功留下余量，拒绝保留源物品。服务器回传权威槽位、完成序号和网络快照；客户端只接受匹配事务，等待期间保护参与槽位与鼠标物品。

**合成：**终端持有队列与工作站，同网络由规范终端统一调度。手动订单统一进入 `TerminalCraftingExecutor.Submit`，在主线程直接调用既有规划、复核和原子提交；不依赖下一次实体更新。新单独立保留身份，不合并进旧暂停或大额任务。不能立即完成的任务仍由轮转调度和每帧预算处理。规划先走常见低成本路线，失败后有限回溯，支持共享库存、配方组和批量余料。新增制作不被已有成品抵消，保持库存计入现有与在途数量。

提交前重新检查所属任务、真实 CPU、连接、材料、工作站、环境条件与权限，再经事务同时扣料和入库。只能容纳一批时走逐批路径，失败不先扣料。旧 CPU、装配室与单目标结构继续兼容；连接新版终端后统一调度，不强制丢弃旧工作站。旧装配室计时配置不能直接解释为新终端队列的速度上限。

**总线：**原版容器接触格解析到容器原点，按过滤、模式和锁定导入/导出；先准备目标物品再提交源扣除，避免重建异常丢失原内容。第三方存储容器不属于该接口。

**拓扑：**网络通过物理相邻和启用的同频道桥接连接。多格设备使用规范类型与原点。放置、拆除、频道和启停变化使连接缓存失效；合并、拆分同时处理库存视图及策略归属。

0.27.5 的掉落收集器使用三个直接设置、可输入半径及搜索勾选网格。`MEDropCollectorEntity` 将超过 \(256\) 格的值规范为有限哨兵 \(257\)，全世界模式跳过距离筛选，继续遍历 `Main.item` 并执行原有过滤、拾取延迟和容量规则。旧 radius 字段和包体保持兼容；`MENet.ReadCollectorConfig` 在完整有界解码后一次发布设置，剔除无效及重复类型，拒绝非有限半径、截断及尾随数据。清单通过变更代次缓存标记，搜索只在文本变化时重建。终端白色加号在物品图标之后绘制，读取已核验的可合成缓存，不在绘制中规划。

## 联机、界面与生命周期

当前 `MENet.ProtocolVersion` 为 \(9\)。协议域包括账本、存取、槽位、合成、设备、权限、玩家、库存页和分片。包体变化必须更新协议，并统一升级服务器和客户端。

权限快照按接收者权限发送；完整解码和校验后统一发布，撤权清理陈旧管理状态。远程终端采用汇总与设备快照，不能依赖附近存在全部本地实体。

窗口分主层、设备层和覆盖层，`AEUiSession` 控制输入、绘制层与鼠标物品占用，`WindowLayout` 保存布局，详情面板提供导航和说明。查询索引、规划预览和显示快照都不能绕过服务端检查。

0.26.2 将窗口底板改为平面边框，物品网格、槽位及图标共用黑色细描边，状态通过底色和角标表达。NPC 目录使用原生背包格底图及现有 `NpcVisuals` 立绘，不显示常驻名称，默认按已加载的图鉴索引排序。合成目录取消底部两行标签，工作台槽位仍由 `UIStationGrid` 管理；只有读取失败时保留底部权限提示。此次只调整界面，不改变配方条件、库存、存档结构或网络协议。

0.26.3 移除合成目录标题并左对齐筛选。`UIBrowserDetails` 使用有界页面历史，保存身份或 NPC、页签、配方、数量及各自滚动位置；历史不落盘，重载时重建。终端消费同一页面数量，NPC 页面清除操作目标。`UIStatus` 合并相同文字和颜色的活动提示，持续触发只刷新时间，不重复挤满屏幕。未改变存档结构或协议。

0.26.4 驱动器去掉 `UIPlayerInventoryPanel`，开窗同时打开原版背包，右侧内容和分区面板延伸到底部。手动订单返回真实执行状态；后台具名任务完成时，通过现有 `ServerNotice` 仅通知请求人，单人使用同一条状态提示。部分完成不冒充整单完成，匿名保持库存不弹完成通知。没有增加保存字段或修改协议包体。

`StorageSystem` 创建索引与规划器，最终配方和阶段数据在 `PostSetupRecipes` 重建；来源索引等待内容注册完整后建立。卸载和换世界时清理相关静态状态。客户端核心夹具运行在加载完成的菜单绘制线程，避免与后台加载并发借用全局状态。

0.26.6 将详情返回统一到 `UIBrowserDetails.Back()`：历史为空调用现有 `Close()`，否则恢复上一条记录；JEI 与合成终端共用此规则。关闭回调继续恢复目录布局及工作台槽位，不新增保存字段或清空既有历史。

## 扩展原则

0.27.0 将当前详情返回栈与 `BrowserHistory` 最近访问日志分开：关闭详情清理导航栈，日志持久保留最近十次。`BrowserContent` 负责稳定内容名、配方摘要和运行时解析，`BrowserPreferences` 负责有界读取、原子替换和前一份备份；异常文件保留原件。`BrowserFavorites` 兼容旧数组并保存配方、数量、显示偏好。这些数据留在客户端，不写入世界、不增加协议包。

`BookmarkTree` 为 JEI 和收藏树共用的增量查询图。显式栈在循环首次出现的材料处回退整个转换分支，尝试其他配方，无法展开时保留缺料叶节点。`RecipeTreeStock` 只修改预览余量；回退时退还子分支的预留，按收藏顺序共享库存。收藏树每次重复需求都继续展开和抵扣，不能只显示引用而跳过材料；不带库存的查询树仍可复用引用。两处均不修改实际账本或替代权威规划器。

`FavoriteTreeHud` 共享帧预算，按收藏顺序处理多棵树，虚拟绘制可见行；标题拖动结束才保存位置，保存字段向后兼容旧收藏。`PinnedInventory` 优先当前终端、再最近终端、首次角色绑定。后台复用现有服务端授权、分片快照和拒绝回包；`TerminalReadState` 为前后台分配不同代次，库存回包分别发布，不污染窗口策略或机器状态。拒绝时清除快照并提示来源；读取重试保持同一代次，避免大快照一直被打断。来源或数量变更重建预览，通常库存检查按固定间隔进行；换世界、卸载与夹具隔离清理相关状态。`AEUiSession` 仍确保前方窗口优先，收藏树拖动时保持指针归属。

`ArmorSetIndex` 按帧查询并缓存组件组合，使用游戏的 `IsArmorSet` 匹配契约。`ArmorSetText` 在独立预览对象上读取受限的描述副本：去除字段、外部数组及间接写入，阻断未批准调用、回跳及自定义异常流，在取得说明后直接退出，不靠异常控制普通流程。本地化格式化只使用有界的自建参数数组；模组数值字段只允许已注册物品类型且静态初始化器为简单常量赋值。灾厄的百分比格式化改由本项目的纯数值函数完成，不执行其装备或工具方法。不会调用真实 `UpdateArmorSet`、装备更新或战斗效果；本地化键可作为静态说明补充。不能可靠读取的动态说明明确提示，当前穿戴时可读取游戏已经计算的奖励。该适配依赖当前 tML 的方法结构，更新 tML 时必须重新运行描述与无副作用回归；不能据此声称能安全执行任意第三方代码。

`UIBrowserCategoryBar` 使用原生物品／NPC 资源和悬停文本，纯图标控件没有文字最小宽度。`UIItemGrid` 将绘制放在原生裁剪子画布，绘制和命中均覆盖不足整行的可见部分。`UIBrowserDetails` 将材料压成单行，工作站与环境合并，长内容使用同一滚动区域；工作站名称补用原生地图条目。

0.26.5 将窗口默认几何集中到 `WindowGeometry.Compact()`；`.compact1` 布局键在首次打开时忽略旧尺寸，保留旧记录供回滚，后续仍读取新键。尺寸统一基于 `PlayerInput.OriginalScreenSize / Main.UIScale`，避免在已缩放的 UI 上下文中再次缩放 Main 屏幕尺寸。窄分类栏、驱动器和管理页根据实际宽度重排。

`MovableWindowState.RequestLayout` 在子控件更新期间只标记待重排，等完整子树更新结束后调用 `ApplyLayout`；下拉菜单自我移除也使用 `AfterChildUpdate`。这是为修复父级枚举期间移除、追加控件的异常。手柄保存初始抓取偏移，限制窗口尺寸，并在尺寸未变时跳过重算。静态排版检查必须与连续完整更新和真实输入旅程搭配。

尺寸参考为 [Recipe Browser 的配置默认值](https://github.com/JavidPack/RecipeBrowser/blob/1.4/RecipeBrowserClientConfig.cs)及[顶部按钮定义](https://github.com/JavidPack/RecipeBrowser/blob/1.4/RecipeBrowserUI.cs)，2026-10-16 核对提交 `f23758a6397898701149d42c51de64314cb4447a`。仅参考尺寸和交互，使用项目自身代码；仓库未发现明确许可证，不复制其实现或资源，不新增运行依赖。

新增设备优先实现现有存储/分区契约，物品身份沿用统一 codec，操作接入共享业务、权限、保存和协议。新增执行路径同时说明回调安全、原子性及预算。接口、包体、保存字段、缓存失效或 UI 行为改变时，修订本文件和[需求与验收](requirements.md)。

## 0.27.6：类别计费与获取阶段

`StorageLedger` 保留完整 `ItemKey` 数量字典，同时维护按基础物品类型索引的合计数量。类别数、字节类别开销和每类数量限额按后一索引计算；插入、取出、恢复、清空及事务替换同步维护两者。旧存档和快照仍逐份序列化完整身份，不需要迁移世界字段，加载重建合计并保留超额库存。数字奇点仍使用 Int64 限额，降级检查改为检查同类型合计。容量语义变化将协议提升至 \(9\)，避免混用旧逻辑。

阶段推导用工作队列更新最早可达阶段，合成取材料、工作站和条件的最晚门槛，多路线取最早；新增采矿边须同时满足矿脉生成和已知可得工具镐力，不允许矿石与其工具互相无源启动。记录来源说明与配方瓶颈，绘制和悬停复用缓存。已建模来源包括基础资源、BossChecklist 的 Boss／事件资料、部分原版小怪、商店、原版主要矿物，以及灾厄机械矿物重做和多年生矿脉；不执行第三方 CanDrop、SpawnChance 或模拟击败 Boss。无法确认的条件保持未知。

Boss 顺序的默认记录保留 NPC、掉落和击败回调。个人顺序只重排完整记录，并重新锚定索引，不改世界状态；旧配置中的已知名称可映射到原记录。`AE2-BossOrder.json` 使用稳定阶段标识和原子文件替换，测试由 BrowserPreferences 隔离。新出现的未列出阶段保留提供方顺序追加，暂时禁用模组的记录不会替换成名称猜测。编辑页先维护草稿，保存失败不修改活图，恢复默认取当前提供方默认记录。

分组网格缓存显示行到实际条目的映射，标题不可选中；滚动、缩放、键盘跟随及 R 命中均使用同一映射，保留不足整行的原生裁剪。正倒序只改变各排序条件方向，未知阶段仍在末尾；阶段模式的收藏仅在各阶段内部优先。加号为细白色十字及黑色描边，仍只读取已核验可合成缓存。

实现核对（2026-10-18，北京时间）：沿用 [BossChecklist 官方接口资料](https://github.com/JavidPack/BossChecklist/wiki/%5B1.4.4%5D-Other-Mod-Calls)；灾厄世界变化依据 [官方源码 NPC 解锁处理](https://github.com/CalamityTeam/CalamityModPublic/blob/1.4.4/NPCs/CalamityGlobalNPCLoot.cs) 及 [配置定义](https://github.com/CalamityTeam/CalamityModPublic/blob/1.4.4/CalamityConfig.cs)。未引入新依赖或复制第三方实现；适配读取当前已加载资料和配置。

## 0.27.7：方向独立与来源比较

查询、终端、设备内容的方向由独立箭头按钮切换，排序下拉只选择排序依据，Boss 顺序入口保留。按钮独立布局、悬停说明；设备列表的共享方向变化参与重建缓存。紧凑窗口的箭头从原排序区域分配宽度，不增加工具栏行。

`ProgressionWorldSources` 声明可确认的自然采集、早期宝箱和钓鱼箱来源，生命水晶天然来源直接为开局。它不从 createTile 推断自然生成，也不扫描当前世界后将困难模式生成物误标成开局。容器只使用原版已知行为及 BossChecklist 标准宝藏袋资料；钥匙和可解释掉落条件共同限制开启阶段。任意模组容器可能有未在掉落表公开的 RightClick 门槛，不能仅因存在掉落表就视为可无条件开启。

工作队列将来源与配方双向通知：新的来源可降低材料、工具、工作站及依赖配方的最早阶段；新的制作路线也可提前获得容器或钥匙。多路线始终取最早，有源链才传播，不允许无源循环自举。保留自然采集或宝箱说明，不被较晚合成覆盖。

最后一次性统计所有已知物品最早阶段与所有已知配方首次可制作阶段，合并为有效检查点。纯掉落新物品独立保留；没有两类新增内容的检查点仅从网格分组和下一检查点说明略过，原时间轴、NPC 资料、个人顺序和实际来源索引保留。统计不读取当前筛选列表，正倒序都用同一份有效节点索引。

核对依据沿用实际 tModLoader 和 BossChecklist API，并复核 [tModLoader TileLoader 官方实现](https://github.com/tModLoader/tModLoader/blob/1.4.4/patches/tModLoader/Terraria/ModLoader/TileLoader.cs) 与 [Recipe Browser](https://github.com/JavidPack/RecipeBrowser)。TileLoader 的类型／样式掉落查询不提供“世界自然生成”证明，因此沿用明确来源声明及现有索引，不增加外部依赖或复制第三方实现。尚无统一公开资料的第三方世界生成或容器条件继续保持未知。

## 0.27.8：钓鱼来源

`ProgressionFishingSources` 使用经 Wiki 与实际游戏版本核对的原版来源，按普通水域、生物群系、熔岩、宝匣和渔夫奖励声明门槛，由 `ProgressionWorldSources.Seed` 接入已有最早路线传播。较晚的事件掉落和模组配方不会覆盖更早的钓鱼来源；地牢匣同时要求骷髅王和对应模式，黑曜石剑鱼保持困难模式检查。统计仍按全体内容，未知第三方钓鱼回调不执行模拟。版本及证据维护在[来源核对](acquisition-sources.md)。

## 0.27.9：统一来源依赖与条件

`ProgressionWorldSources.AcquisitionRoute` 表示输出、永久门槛、全部必需输入及说明。容器和钥匙、直接微光、标准提炼机、牡蛎内容共同建立输入反向索引；任一输入阶段下降时重新检查整条路线，并通知配方和采矿工具队列。无源环不能启动，玩家显式覆盖仍优先。每次重建只读取声明数据，不调用获取物品或判定回调。

Boss 掉落和宝藏袋读取完整 DropRecord，合并附加门槛；BossChecklist 清单不能覆盖已经报告的条件。事件内独立 Boss 使用更具体的非推断检查点，高级事件 NPC 另加生成门槛。Fargo 难度适配限已审阅版本，未知谓词不默认可得。GameDataIndex 额外读取 ContentSamples 中的负数变体净编号，保留独立掉落和名称；来源页对这些变体展示正确文字，不将负数传入普通 NPC 贴图和历史接口。

`AcquisitionAudit` 只在显式核心回归中导出当前阶段、理由、掉落条件和商店声明，输出在本机诊断目录；正常游戏不导出，不读写玩家世界保存。资料与覆盖边界集中于 acquisition-sources.md。

## 0.27.10：按依赖追查未知来源

掉落门槛适配同时取得条件类型和掉落者身份。Fargo 1.7.3.9 的提前生成普通奖励锁仅对已审阅原版 NPC 声明困难模式门槛，未知来源不套用；原版 NotUsedDemonHeart 是角色消耗状态，取得阶段由宝藏袋决定。新增陆龟、愤怒雨云、World Feeder、猪龙和红魔鬼等生成门槛，配方继续使用统一工作队列。审计导出附带材料、工作站、条件和容器记录，定位未知材料根因；数据只在显式回归中写本机验证目录。
