## 可直接使用的交互改善

- 合成预览使用实际下单数量，显示批次产物和中间余料；缺料和材料行可左键查来源、右键查用途。
- 终端和存储内容搜索可组合关键词、`@模组名` 和 `!排除词`；继续支持已有中文、拼音与词缀搜索。查询条件属于临时界面状态，不写进世界，不需要联机保存。
- CPU 的任务和“保持库存”分别分页，补货项较多也能查看与取消；底层保持库存数据仍由原 CPU 存档和服务端快照保存同步。
- 单格、同类、批量存入共用规则；词缀及自定义身份可以分别选择；部分成功会保留余量并报告实际数量。
- 换盘容量不足、产物空间不足、锁定材料、队列暂停、特殊配方等状态给出下一步提示。
- 驱动器分区与内容切换不再叠画；窄窗口按钮换行；终端背包格随宽度调整；容量/进度条不再使用不适合薄条的面板贴图。
- 只更新最上层活动窗口的交互，减少点击穿透；输入期间抑制冲突快捷键；保留拖动、缩放和已有布局文件。

新增持久任务标识、世界隔离的远程绑定和网络成员策略都有兼容读取及同步路径。没有引入需要玩家重新建网或重做存储的迁移操作。

## 已知边界与未完成验证

1. 没有运行两名真实客户端加入服务器进行完整操作。鼠标物品跨原版同步与 ME 请求的高延迟、断线时序，大快照分片压力、远程终端距离切换以及权限撤销的实际交互仍需联机验收。不能把序列化回归当作这些场景已经通过。
2. 没有进入用户实际世界执行整段存取、换盘、拆除、多人自动化和退出重进操作。存档验证使用隔离对象的 SaveData/LoadData 往返及真实存档文件完整性比较。
3. 自动合成不等价于任意模组的原版玩家合成流程。直接特殊回调和 ModItem 创建规则已保护；GlobalItem.OnCreated、特殊材料消费钩子以外的全局游戏挂钩、动态环境和任意副产物不能保证全部等价。涉及这些规则的模组配方仍需要专项兼容验证。
4. 规划器有深度和工作量上限，并非全局最优搜索；复杂循环与资源竞争的替代路线可能显示不可达或缺料。不能承诺每个理论可行配方都能找到最优方案。
5. 已有旧存档若只有运行时数字编号且此前发生过模组编号变化，无法证明原始身份；旧版本已丢掉的自定义数据也无法恢复。新格式防止继续发生同类问题，不能自动修复历史损失。
6. 存储总线仍会周期扫描原版箱子；尚未测量大型箱子网络、长期自动化和大库存运行的耗时、帧率或内存曲线。唯一量化性能证据是未变化库存的聚合重建计数。
7. 未对真实中文输入法候选窗、所有分辨率/缩放组合、所有其他模组窗口覆盖层逐一手工操作。当前验证覆盖实际控件绘图、所列布局、两种标签切换与静态输入路由检查。
8. 身份保存遵循第三方模组自身 ItemIO 保存契约；未实现 SaveData/LoadData 的瞬态自定义状态不能由本模组替其保存。服务端仍依赖 Terraria 原版玩家库存同步，不是通用反作弊系统。

## 复核入口

核心回归由 `AE2_RUN_REGRESSION=1` 显式开启，在 `PostAddRecipes` 执行。UI 绘图额外设置 `AE2_UI_REGRESSION=1`，只在客户端主菜单、模组加载完成后运行。默认玩家游戏不会执行这些测试。

构建、服务端加载命令见项目 AGENTS.md；服务端测试必须不带 `-nosteam`，并停在世界选择菜单。启动客户端前应先告知使用者。不要通过覆盖、重置或删除存档来复测。
