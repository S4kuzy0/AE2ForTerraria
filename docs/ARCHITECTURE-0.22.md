# AE2 for Terraria 0.22 系列：架构与实施记录

日期：2026-09-21。源码基线为本次修改前的 0.21.0 备份；交付版本为 0.22.1。判断依据是源码、运行回归和实际客户端绘图，不是 README 中的功能描述。

## 目标架构及已落实的边界

采用现有规模可以维护的直接调用结构，没有引入服务容器、事件总线或数据库。原有方块实体、物品、配置和查询入口保留。

| 模块与文件 | 职责 | 调用和依赖 |
| --- | --- | --- |
| `Core/ItemKey.cs`、`ItemPersistence.cs` | 完整物品身份、实际 Item 的重建、稳定存档身份、缺失模组占位数据 | 调用 tML ItemIO；使用 TagCompat 读取旧数字字段。身份不包含数量或收藏标记 |
| `Core/StorageLedger.cs` | 数量、容量、版本、模拟存取、无容量损失的恢复 | 不负责界面、世界掉落、权限或联机 |
| `Core/StorageTransaction.cs` | 合成消耗和全部产物先试算，成功才一起提交 | 只依赖 IMEStorage 与账本；提交期间不执行外部合成回调 |
| `Systems/StorageOperations.cs` | 玩家背包单格、同类、批量存入及安全取出 | 单人与服务端共用；以真实 Item 和账本为依据，保留部分成功的余量 |
| `Systems/MENetwork.cs`、`NetworkInventory.cs` | 连通网络、存储列表、跨网搬运、聚合读视图 | 方块实体提供存储；账本身份和版本决定聚合缓存是否有效 |
| `Systems/NetworkRegistry*.cs`、`WirelessRegistry.cs` | 世界内名称、所有者、权限、锁定清单、无线连接和策略归属 | 原策略关联保存在成员坐标上；当前最小坐标仅作网络入口 |
| `Core/RecipeIndex.cs`、`CraftPlanning.cs`、`RecipeExecutionPolicy.cs` | 配方正反向索引、材料与替代材料试算、精确批次产出、安全边界 | 规划器每次调用独立；只返回计划，不扣料；实体提供工作站和条件过滤 |
| `MECraftingCpuEntity` | 持久任务、请求人、暂停、排序、保持库存 | 队列与执行分离；任务有持久标识，补货使用同一队列 |
| `MEMolecularAssemblerEntity` | 选择任务、逐批推进、重新检查条件、提交事务、反馈结果 | 使用同一个规划器和事务；多个装配室各自推进一次 |
| `Systems/MENet*.cs` | 意图请求、服务端校验、序列化、分片快照、订阅和远程显示 | 由服务端执行业务；客户端副本只服务显示。旧槽位快照上传停用 |
| `UI/*`、`Systems/UISystem.cs` | 窗口、输入、选择、预览、提示、可见状态 | 调用公共业务操作或发送意图；不再自己实现另一套取出和部分存入规则 |
| `RegressionChecks.cs`、`UiRegressionSystem.cs` | 显式启用的核心回归与客户端绘图 | 默认不运行；测试不读取或写入世界、角色存档 |

`Core` 仍使用 Terraria 类型，不是独立的无引擎类库。搜索规则目前由 `ItemSearch` 共用，并使用既有物品名、拼音和显示来源工具；没有为这个小模块再抽一套接口。存档兼容辅助 `TagCompat` 也仍沿用现有工具。

## 主要调用流程与一致性

### 查询、来源和用途

`StorageSystem.PostAddRecipes` 最终建立 `RecipeIndex`。产物索引用于合成查询，原料索引包含配方组的替代材料，用于用途查询。原有 `GameDataIndex`、`AcquisitionRegistry`、`ProgressionGraph`、物品和 NPC 浏览器保留。它们负责获取信息；不能把资料索引或阶段推断当作配方可执行的证明。

终端读取网络聚合快照，搜索和排序只在库存版本、查询或排序改变时重建列表。`UIRecipePanel` 按下单数量调用规划器；实际执行前仍重新规划并检查容量。材料与缺料行可以直接进入来源或用途页。界面中的“参考配方”明确不是规划器保证采用的唯一配方。

### 存取和搬运

单人界面调用 `StorageOperations`；多人界面发送格子、预期身份、范围、数量等意图。服务器重新读取玩家背包并确认权限。账本返回实际完成数量，背包只扣这个数量；收藏物品不自动存入。

取出先确认真实库存、完整身份和空闲掉落槽，再创建物品并扣对应数量。掉落槽满时库存保留，防止 Terraria 的 `NewItem` 覆盖旧掉落。普通“取出”仍沿用在玩家附近生成可拾取物品的既有习惯；“清空到地上”附带拾取延迟，不能把它描述成已直接放入背包。

当前存储块窗口的取出请求带有范围，服务器不会改为从整张网络扣账。“清空到地上”的模式也随请求传递。跨网搬运拒绝重叠存储，并按目标能接收的数量搬运。

### 自动合成

规划记录精确消耗、每批产物和中间余料，支持多配方、混合配方组、批量产出、循环终止和预算限制。制造新目标时保留已有同类库存。执行一次批次前重新规划，在账本副本中检查扣料后的所有输出容量与分区，成功后才替换真实账本。

暂停、取消、断网在继续扣料前检查。队列取消和排序使用持久任务标识，避免其他任务完成后原索引指向不同任务。补货任务没有玩家投递归属，产出留在网络。多装配室按游戏线程顺序提交，后执行者看到前一次提交后的库存；不再各自乘一次全网装配室数量。

配方条件仍使用 tML 的条件函数；静态工作站支持已补充的原版高阶替代和 ModTile.AdjTiles。任意模组的动态玩家环境、GlobalItem 创建钩子和副作用尚不能视作完整模拟。发现直接配方合成/消耗回调、ModItem 自定义创建或特殊输出数据时，自动化会保留原料并提示手动制作。此保护扩大了正确性边界，不代表实现了这些特殊配方。

### 存档和网络

新保存的条目使用 ItemIO 的稳定模组名、物品名、词缀及自定义数据。仍可读取旧 `type/prefix/amount` 字段。载入是恢复，不按尚未装好磁盘的容量重新“存入”；超容量旧数据可以取出，不能继续存入。

模组缺失时保留 ItemIO 的 UnloadedItem 原始数据。过滤器中的缺失物品引用也保留；仅包含缺失物品的白名单不会退化为接收全部。旧版本已经丢失的自定义数据、只有数字编号且已经变动的旧身份无法凭空恢复，因此保留了完整源代码与存档备份。

网络名称、权限与锁定清单随成员策略继承。不同所有者的网络合并取较严格的权限，拆分后各自恢复原策略；不能通过接一根线获得另一网络的管理权。无线频道改动、方块变化、世界切换均使相关缓存失效。角色远程绑定按世界标识隔离。

联机协议为第三版。服务端既校验操作权限，也过滤账本、磁盘和任务快照的接收者。大快照分片组装后再解析；单个账本解析完整才发布，截断数据不会先清空原显示。远程汇总和 CPU/装配室显示不再依赖本地方块实体是否已加载。客户端和服务端必须使用相同版本。

## 保留、拆分和替换

- 保留现有内容 ID、方块类型、主要配置键、查询资料索引、工作站槽位、CPU 队列入口、快捷操作和 UI 窗口体系。
- 用 `CraftPlanning.cs` 替换原 `CraftPlanner.cs` 的共享状态与推测产量逻辑。
- 把身份读写、库存聚合、玩家存取、合成事务从各界面和实体中收拢到公共实现。
- 保留 MENet 的分文件结构，增加意图操作、角色状态和分片模块；停用直接信任客户端整份磁盘/工作站数组的写入入口。
- 保留原版箱子总线。因旧的单一箱子签名遗漏网络容量和库存变化，改为有界周期重试；没有把错误缓存继续当作性能优化。未接入 Magic Storage。

中间版本 0.22.0 及完成版本 0.22.1 均按完整源码路径构建，直接安装到实际默认目录。没有在线迁移脚本或世界结构重建。持久数据增加新字段并兼容旧读法，但旧版程序不理解新身份格式；恢复旧版本时应配合本次备份，不应让旧版继续保存已由新版写入的数据。

## 性能依据与边界

`NetworkInventory` 用实际账本引用和版本比较，缓存最多 \(64\) 份；拓扑缓存、远程对象和分片组装也有上限与世界切换清理。`UITextCache` 改为弱键，不长期持有已关闭窗口。条件失败缓存定期重查，避免环境变化后永远停住。

回归中连续 \(1001\) 次读取未变化库存，仅重建聚合 \(1\) 次；一次账本变动后重建次数变为 \(2\)。这是可复核的工作量变化，不是 FPS、耗时或内存下降比例。没有完成长时间大世界性能测量。物品完整身份序列化、复杂递归规划和箱子周期扫描仍可能成为大规模场景成本，不能宣称已消除卡顿。
