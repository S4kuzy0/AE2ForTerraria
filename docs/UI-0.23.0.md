# 0.23.0：已确认浏览器 UI 的游戏实现

本版依据用户最后确认的紧凑预览实施。用户已于 2026-10-10 取消后续更新前必须预览并确认的限制；当前流程以根目录 [AGENTS.md](../AGENTS.md) 为准，需要先规划时由用户使用 `/plan`。

## 已落地

- 查询窗口顶部为物品、配方、怪物 / NPC；收藏在右上角。移除品牌标题和常驻操作说明。
- 主分类及子分类沿用 Recipe Browser 的名称与属性规则。材料是筛选条件，不另加主分类；分类按可用宽度换行，无子分类不留空行。
- 默认目录铺满窗口；点击才打开右侧覆盖详情，目录大小、滚动位置和列表版本不因选择改变。第一次展开使用短动画，已展开时更换条目不重复入场；收起、返回、前进可用。
- 详情包含配方、来源、用途、合成树。支持多配方切换、配方组的替代物、工作站、环境条件以及材料点击查询。合成树不再是一级页面。
- NPC 目录使用全部已加载 NPC，可筛选敌对、Boss、城镇居民、小动物和其他友好生物；详情显示基础属性、掉落概率和已声明的掉落条件。
- 名称 / 拼音、模组、材料、配方和掉落来源筛选；物品属性排序；右键 / U 查用途，R 查配方，双右键反查掉落 NPC，Ctrl 或 Alt 左键收藏。
- 收藏按原版身份或模组内部名称保存在默认存档目录 AE2-BrowserFavorites.json；物品和 NPC 使用不同命名空间，禁用模组不删除收藏记录。它是本机个人显示偏好，不是服务器库存或队友共享收藏。
- 终端提供已储存、可合成、已储存 / 可合成。保留精确物品身份、词缀、批量取出、背包存入、数量输入、CPU 下单和维持库存；背包由顶部按钮展开。
- 物品悬停交给 Terraria 原生提示系统，以真实 Item 及自定义数据生成提示；NPC 提示使用名称和类型。

## 实际模块职责

- UI/BrowserCategories.cs：读取已加载物品 / NPC 属性，提供分类及有边界的分类结果缓存；卸载时清除。
- UI/UIBrowserCategoryBar.cs：分类换行和选中状态，不参与物品修改。
- UI/UIBrowserDetails.cs：当前选择、历史、详情页和可滚动内容；换行只在内容或宽度改变时重算。
- UI/BrowserFavorites.cs、BrowserHover.cs、UIChoiceMenu.cs：分别负责收藏偏好、原生悬停信息和临时选择列表。
- UI/SearchUIState.cs、TerminalUIState.cs：组合上述控件；终端继续调用原有 StorageOperations / MENet / CPU 请求流程，不另造一套存取或权限判断。
- Core/RecipeIndex.cs：配方产出及用途索引，同时提供已索引的产出类型，避免每次终端筛选扫描全部物品。
- Systems/StorageSystem.cs：在 PostSetupRecipes 中建立最终配方索引。测试所需的临时配方仍在允许创建配方的 PostAddRecipes 阶段运行。
- Systems/GameDataIndex.cs：查询来源、NPC 反查和商店声明。读取商品条件而不执行条件谓词，避免把当前锁定商品永久漏出目录。

## 已确认的问题与修复依据

1. **配方错位**：原索引在 PostAddRecipes 记录数组位置；加载结束后的配方排序会改变该位置。真实客户端曾显示“泰拉刃”标题和“抓钩”配方。已改到 PostSetupRecipes 建立索引，并检查所有索引产出与最终 Main.recipe 一致。
2. **切换详情闪动 / 悬停触发规划**：移除终端悬停后自动 Select，改为点击更新覆盖详情；目录不因选择而重建。
3. **详情遮挡下的鼠标状态**：网格排除详情和选择菜单覆盖区域，离开时同时清空 HoveredType / HoveredKey；物品高亮使用完整 ItemKey。
4. **NPC 误加载物品贴图**：原格子在 NPC 分支前调用 LoadItem(npcType)。现在只在物品分支加载物品贴图。
5. **带词缀库存遮蔽可合成条目**：合并列表按完整身份去重，带词缀成品与无词缀配方产物分别保留。
6. **后台刷新重开详情**：存取刷新仅更新已经打开的详情，收起后不会因库存变化重新弹出。
7. **商店来源遗漏**：原实现调用 FillShop 并缓存当时满足条件的结果。现读取 NPCShop 商品声明及条件文字，避免在无 NPC / 玩家上下文时执行第三方条件。

## 验证范围

实际验证结果见 ../validation/ui-0.23.0-report.json 和同目录保存的客户端 / 服务端日志、渲染图。渲染在真实客户端及当前启用模组环境进行，使用内存中的临时网络，在主菜单运行，不打开或保存世界与角色。

本轮没有完成真实世界中的多人交互、中文输入法候选词手动输入、长时间运行和所有模组掉落规则组合的人工验收，不能用构建或菜单渲染代替这些验证。

## 与 Recipe Browser 完整对等仍有差距

本次已落地确认的布局和主要查询流程，不能据此声称 Recipe Browser 全功能对等。完整套装分组 / 套装奖励、队友收藏同步、图鉴解锁状态、旅途研究状态、附近箱子制作可行性、全部分类专属筛选及排序仍未全部实现。“套装”目前是装备部件目录；查询合成树用于展开配方，并不证明该路线在当前环境可执行。终端实际执行仍由原有规划器验证。

仅支持动态 FillShop、未提供 NPCShop 静态商品声明的自定义商店仍不能完整索引。存储总线仅支持原版箱子是用户确认的设计，本轮没有改变。
