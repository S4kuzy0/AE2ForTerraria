# 0.23.1：确认后的 JEI 紧凑布局与菜单修复

用户已明确要求将 `jei-browser-dense.html` 对应调整写入代码并安装。保留现有 `SearchUIState.v3` 布局键、分类内容、查询与详情流程，不迁移角色、世界或库存数据。

## 改动

- 右上工具栏依次为筛选、帮助、收藏、重置、关闭；收藏与重置同尺寸，全部模组仍独占搜索行右侧。
- 分类采用紧凑字号、高度与内边距，保留原有主分类及子分类；无子分类时不占空行。
- 排序框和红扳手同宽同高。作弊功能继续遵守原服务器配置及权限规则，关闭作弊配置时隐藏扳手并回收空位。
- JEI 四条边框全部用于移动，不绘制悬停高亮。删除额外的角落缩放命中区，仅保留可见斜线手柄。列表空白可拖动，物品、输入框、按钮及滚动条保持原操作。
- 模组下拉选项从实际目录物品的归属生成，并在目录建立时缓存；不会列入没有目录物品的模组。按下拉框选择使用精确归属比较，避免选中 `Fargowiltas` 时混入 `FargowiltasSouls`。手动输入 `@` 查询仍支持模组名部分匹配。
- 筛选按钮保留固定标签，启用条件时用选中状态提示，避免长条件名撑大工具栏。

## 源码依据与职责

- `UI/UITheme.cs`：图标按钮继承了空文本面板的最小高度，设置目标高度后仍被撑大；现清除图标及页签的文本最小尺寸，按照实际布局绘制。`UIButton.Flat` 用于紧凑分类的非选中状态。
- `UI/SearchUIState.cs`：组合工具栏、紧凑分类及物品目录，生成有物品的模组选项；原有物品、NPC、配方与作弊调用流程保留。
- `UI/UIBrowserCategoryBar.cs`：新增紧凑排版选项，仅对本次 JEI 方案启用；按实际文本宽度换行。
- `UI/UIChoiceMenu.cs`：触发按钮归入自己的菜单区域。按下触发按钮不再提前关闭菜单，松开时统一切换；只重算浮层自身，不触发整个宿主重新排版。窗口移动或缩放时浮层跟随触发按钮。
- `UI/MovableWindowState.cs`、`UI/UIWindowFrame.cs`：由 JEI 指定仅角落缩放和无边框高亮，其他机器窗口保留现有边框模式；普通按钮松开不再误触窗口移动回调。
- `UI/UIItemGrid.cs`：鼠标命中查询使用当前布局，拖动判断不依赖上一帧的悬停条目，防止点击物品时误拖窗口。

筛选修复针对已确认的“按下关闭、松开重建”事件路径。真实客户端回归验证其菜单实例、目录版本及滚动位置稳定；这不是对所有可能来源的整屏闪烁作无限保证。
